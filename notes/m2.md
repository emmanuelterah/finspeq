# M2 — Crashes and delivery guarantees: results

- **Date:** 2026-11-26
- **Data:** the M1 slice (card slice 20:0, 2026-03-01 → 2026-06-15): 115,720 events, 417 cards, one
  partition
- **How:** `bash scripts/m2_drills.sh`; raw reports in `notes/m2/`
- **Status:** complete. Every exit criterion is met.

## 1. Tooling

| Piece | Behaviour |
|---|---|
| Worker fault injection | Seeded crash points after poll, after apply, after ack; `os._exit(137)` skips cleanup and commits |
| Consumer rejoin | 6 s session timeout and static membership (`--instance-id`): a restarted worker gets its partition back without waiting for the dead member to expire |
| `scripts/crash_drill.py` | Restarts a command until it exits 0; after each exit records the stored position (Redis) and the committed group offset (Kafka); optional Redis SIGKILL |
| `experiments/naive_counter.py` | `INCR` per card, then a synchronous offset commit; `compare` measures the over-count |

## 2. Naive counter vs feature worker under the same crashes

Crash point: after the write, before the offset commit; probability 0.05 per 50-event batch.

| | Naive counter | Feature worker |
|---|---|---|
| Crashes | 114 | 108 |
| Events counted / applied | 121,420 of 115,720 | 115,720 of 115,720 |
| Over-count | **5,700 events (4.93%)** | **0** |
| Amount over-counted | $353,039.24 | $0 |
| Cards affected | 405 of 417 | 0 (verify-state: 0 window mismatches) |

The naive over-count is exactly 114 × 50: every crash re-counts the batch whose offset was never
committed. The feature worker skips those events because its position is stored with the state
in the same Lua call (ADR-003).

## 3. Stored position vs committed group offset (experiment 3)

After **all 108** worker crashes the committed group offset was behind the stored position, by
up to **150 events**. A crash after apply leaves one 50-event batch uncommitted; the worker commits
group offsets asynchronously for lag reporting, and `os._exit` discards commits still in flight,
so the group offset trailed by up to three batches. Recovering from the group offset would have
re-applied those events; recovery from the stored position re-applied none.

## 4. Redis SIGKILL mid-run (AOF `everysec`)

| | Value |
|---|---|
| Stored offset read ~1–2 s before the kill landed | 36,249 |
| Stored offset after Redis restarted from its AOF | 38,399 |
| Events applied by the restarted worker | 77,320 (= 115,720 − 38,400) |
| verify-state | **0 window mismatches**; offsets cover all 115,720 events |

The worker failed with `StoreUnavailableError` (exit 1) and was restarted. It resumed exactly at
the position Redis recovered, so state and position rolled back together. The number of events
lost from Redis and re-applied was not measured: the drill read the position before the kill
command completed, while the worker was still applying.

## 5. Total loss and durability costs

| Drill | Result |
|---|---|
| Rebuild an empty store from offset 0 (AOF `everysec`) | 115,720 events in 11.8 s (9,845 events/s); 0 mismatches |
| Same rebuild with AOF `always` | 9,885 events/s: no measurable cost |
| Publish with broker `write.caching=false` | 1,599 events/s (72.4 s) |
| Publish with broker `write.caching=true` | 1,756 events/s (65.9 s) |

- AOF `always` is free here because the worker writes once per 500-event batch (about 20 fsyncs
  per second). M5 revisits this if the scoring API writes per event.
- Durable broker acknowledgements cost about 10% of publish throughput, about 28 ms per
  acknowledged chunk. M5 measures the per-request cost on the hot path.

## 6. Issues found and fixed

| Issue | Effect | Fix |
|---|---|---|
| Windows venv launcher: child `python` resolved to the base interpreter | Drill children could not import `redis` | Drill runs programs by absolute path from `PATH`; drill script uses the venv interpreter |
| Drill restarted a failing command forever | 1,000 failing runs possible | Stops after 3 non-crash failures in a row |
| Naive counter committed with `enable.auto.offset.store=false` | `_NO_OFFSET` commit error | Commits explicit per-partition offsets |
