# M1 — Single partition, single worker: results

- **Date:** 2026-11-26
- **Stack:** Redpanda v24.3.1 (1 broker, `write.caching=false`), Redis 7.4 (AOF `everysec`),
  Postgres 16, on Docker Desktop (Windows laptop)
- **Status:** complete. Every exit criterion is met.

## 1. What was built

| Piece | Behaviour |
|---|---|
| Envelope codec | Canonical JSON (sorted keys, compact, ASCII); strict decode; key must equal the card |
| `RedpandaPublisher` | Idempotent producer, `acks=all`, murmur2 partitioner, returns positions after ack |
| `RedpandaSource` | Manual offsets; on assignment seeks to the position stored in Redis (ADR-003); drops buffered events of revoked partitions; one partition per batch |
| `RedisWindowStore` | `apply_batch.lua` validates every argument, skips stored offsets, rejects gaps, keeps the first copy of a tx_id, prunes by event time, and stores the position in one script call; `read_window.lua` reads a window in one round trip |
| `ApplyEvents` + `FeatureWorker` | Poll, apply, acknowledge; stops on signal, after an idle period, or at a start timeout |
| `ReplayHistory` (simulator) | Publishes history in canonical order, by card slice, at a target rate |
| `VerifyReplay` (Level A) | Applies the same batches to memory and Redis; compares every window before each delivery, every apply result, every position; optional redelivery |
| `VerifyFinalState` (Level B) | After a real worker run, compares each card's final window with a memory replay |

## 2. Results

| Check | Result |
|---|---|
| Live-Redis contract suite (14 clauses incl. randomized differential test) | 14 / 14 pass |
| End-to-end integration test (3-partition topic, real worker) | pass |
| Level A, slice 20:0, 2026-03-01 → 2026-06-15, 4 partitions, every 7th batch redelivered | 232 batches, 265 deliveries, 132,220 window reads; **0 window, result, or position mismatches** |
| Level B, same slice, simulate → worker → verify-state | 115,720 events, 417 cards; **0 window mismatches**; stored offsets cover all 115,720 events |
| Worker throughput (one process, 500-event batches) | **9,739 events/s** (target ≥ 2,000) |
| Simulator publish rate | 1,591 events/s (each 500-event chunk waits for its acks, which wait for fsync) |

Level A counts 132,220 events because 33 batches were delivered twice; the store skipped every
redelivered event and the windows stayed identical to the reference.

## 3. Issues found and fixed

| Issue | Effect | Fix |
|---|---|---|
| Redis Lua `GET` on a missing key returns `false`, not `nil` | First batch failed in the script | Explicit check; found by the fakeredis contract run |
| Unexpected script errors reported as invalid messages | Real cause hidden | Only `GAP`/`INVALID` replies map to those errors; others become `PortError` |
| Worker idle timer started before partition assignment | Worker exited with 0 events during the consumer-group join | Idle limit applies after the first event; separate start timeout |
| Port 5432 blocked on Windows | Postgres did not start; topic init never ran | Host port configurable, default 15432 |
| Redpanda `write.caching=true` by default | `acks=all` returned before fsync | Topic created with `write.caching=false` |
| librdkafka tried IPv6 `::1` first for `localhost` | 2 s connection delays and log noise | Clients use IPv4; default bootstrap `127.0.0.1:19092` |
| `bootstrap` imported Prometheus at module level | Offline commands failed without the streaming extra | Lazy imports; a test checks bootstrap loads no streaming library |
