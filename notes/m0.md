# M0 — Offline baseline: results

- **Date:** 2026-11-26
- **Model:** LightGBM, feature set v2, no class reweighting (`models/candidates/v2-none`,
  source model `bf88a0aa9faf`, best iteration 1372)
- **Release model:** ONNX `models/2e632818a205` (thresholds and lineage in `metadata.json`)
- **Dataset:** `data/processed/training_v2`, DATASET.json SHA-256 `863dc9c4…`, built from
  `events_sorted.parquet` SHA-256 `4b7be3b4…`
- **Status:** complete. Every acceptance criterion is met.

All 10 data-quality checks pass (`notes/data_quality.md`). The check found 60 cards with 11-digit
numbers; `CardId` now follows ISO/IEC 7812 (8–19 digits).

**Category–time confound (ADR-009).** Legitimate traffic moves through merchant categories in
time blocks, while fraud uses the same four categories throughout. With `category_code` (v1) the
model put 88% of its gain on that feature, and on a January 2025 split it flagged 20.2% of
legitimate test traffic at the 1%-FPR review threshold. Feature set v2 drops the category and
adds `amount_to_max_24h`; on the same split the review FPR is 1.03%.

## 2. Model comparison (test split)

Recall@x% is the share of fraud caught when x% of legitimate transactions are flagged.

| Model | Valid PR-AUC | Test PR-AUC | Test ROC-AUC | Recall@0.1% | Recall@0.5% | Recall@1% |
|---|---|---|---|---|---|---|
| Rule: night hours, then amount | 0.374 | 0.383 | 0.921 | 0.371 | 0.631 | 0.642 |
| Logistic regression (1/4 of train) | 0.456 | 0.419 | 0.892 | 0.288 | 0.585 | 0.674 |
| **LightGBM, no reweighting** | **0.920** | **0.927** | **0.998** | **0.866** | **0.938** | **0.958** |
| LightGBM, sqrt weight (11.7) | 0.910 | 0.920 | 0.998 | 0.853 | 0.932 | 0.950 |
| LightGBM, balanced weight (137.1) | 0.904 | 0.914 | 0.998 | 0.843 | 0.928 | 0.949 |

**Imbalance (decision D7):** no reweighting is best on every metric. Thresholds are chosen from
false-positive budgets, so reweighting only rescales probabilities and costs ranking quality.

## 5. ONNX export, parity, and latency

All figures are on the full test split (2,496,732 rows), measured on the laptop.

| Check | First export | After the float32 fix | Target |
|---|---|---|---|
| Max abs diff vs LightGBM | 0.039 | 1.2e-6 | ≤ 1e-5 |
| Mean abs diff | 7.8e-8 | 3.2e-8 | |
| Rows over 1e-5 | 40 | 0 | 0 |
| Decision mismatches | 0 | 0 | 0 |
| Single-row latency p50 / p99 / max | 0.17 / 0.34 / 0.66 ms | 0.13 / 0.18 / 0.36 ms | p99 < 3 ms |

Latency varies with laptop load: the release export run measured p50 0.35 ms, p99 1.88 ms, and
max 18.4 ms. Both runs meet the p99 target. M5 will measure latency under controlled load.

**Cause of the parity gap.** LightGBM stores split thresholds as float64. ONNX stores them as
float32, rounded to nearest. 28,963 of 85,064 thresholds round up, and because amounts and spends
are whole cents, real feature values land exactly on rounded-up thresholds and take the other
branch. **Fix:** the exporter rewrites every threshold to the largest float32 not above it
(`float32_exact_model`). For float32 inputs, `x <= t` holds exactly when `x` is at most that
value, so split decisions are unchanged and ONNX stores exact thresholds. The rewritten text drops
LightGBM's `tree_sizes` header, whose byte counts no longer match.

## 6. Determinism

| Check | Result |
|---|---|
| Dataset built twice (laptop, `--jobs 8`) | All 19 part files byte-identical (SHA-256) |
| `v2-none` trained twice | Same model version `bf88a0aa9faf`, best iteration 1372 |
| Canonical event file sorted twice (Linux sandbox, Windows laptop) | Identical SHA-256 `4b7be3b4…` |
| ONNX export of the same artifact on two machines (before fix) | Differed: random graph name |
| ONNX export of the release artifact on two machines (after fix) | Same version `2e632818a205`; identical metadata.json |

The exporter names the graph after the source model version, and a test checks that two exports
of one artifact produce the same version. The first DATASET.json was written with CRLF before the
LF fix; it was rewritten with LF, and the release model records the LF hash.

## 7. Issues found and fixed during M0

| Issue | Effect | Fix |
|---|---|---|
| 11-digit card numbers | Domain rejected 88,018 rows | `CardId` follows ISO/IEC 7812 (8–19 digits) |
| Source converted whole row groups | 2.5x unneeded domain objects | Binary search on `unix_time` per batch; 3.7x faster |
| Category–time confound | v1 test FPR 20% at review threshold | Feature set v2 (ADR-009) |
| CRLF line endings on Windows | LightGBM aborted loading `model.txt` | All generated text written with LF |
| Windows paths in reports | Reports unreadable on other OSes | Paths stored in POSIX form |
| float32 threshold rounding in ONNX | 40 test rows over tolerance | `float32_exact_model` before conversion |
| Random ONNX graph name | Same model exported with different versions | Graph named after the source model version |
| Fixed manifest file name | A second sort run overwrote the first manifest | Manifest named after its file (`<stem>.manifest.json`) |
